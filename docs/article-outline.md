# 问题修复后的文章与教程提纲

## 定位

问题修复后，本仓库不删除历史复现代码。文章将用同一最小案例讲清楚如何设计、观察和验证 AIUI 连续语音交互，同时明确区分运行时生命周期与产品层语音体验。

## 建议标题

《从一次 ASR 假活到可验证的 AIUI 连续语音：最小复现、取证与正确实现》

## 文章结构

1. **为什么一句话会跨多个原生 ASR 分段**
   - 自然停顿与 endpointing。
   - 用户级语音轮次和原生识别会话不是同一概念。

2. **如何把复杂业务缩成最小案例**
   - 移除 LLM、存储、页面跳转和业务解析。
   - 使用单次识别基线与自动续听对照。

3. **生命周期事件仪表盘**
   - `onstart`、声音/语音活动、`onresult`、`onerror`、`onend`。
   - 为什么结构化 `ASR_REPRO` 日志比截图更可靠。

4. **为什么固定看门狗会误伤**
   - 启动时间不等于用户开口时间。
   - 观测型超时与恢复型超时的区别。

5. **修复前后的真机证据**
   - 相同设备、固定语句和轮数。
   - 事件时序对比与隐私脱敏。

6. **修复后的推荐实现**
   - 官方支持的对象复用、重启间隔和终态保证。
   - 页面销毁、中止、晚到回调和状态机处理。

7. **把最小案例导入 Craft**
   - 直接选择 `src/`。
   - 浏览器预览与真机验证的边界。

8. **可复用的测试方法**
   - 单元测试 fake recognizer。
   - ADB 证据采集。
   - 20 次循环、5 秒静默和页面切换回归。

## 教程配套材料

- 一段 3 分钟最小复现视频。
- 一张修复前后生命周期时序图。
- 一份公开脱敏事件日志。
- Craft 导入与真机运行截图。
- 可复制的验证清单。

发布前应把官方提供的修复版本、推荐 API 语义和限制写入正文；如果官方仍未确认，则只发布复现与取证教程，不把假设包装成结论。
