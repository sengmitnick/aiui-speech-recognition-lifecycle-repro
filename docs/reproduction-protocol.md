# 真机复现协议

## 目标

在相同源码、相同设备和相同语句下，对比“单次识别基线”与“自动续听复现”，观察异常是否与 `onend` 后连续再次 `start()` 相关。

本协议不用于测识别准确率，也不证明任何内部根因。

## 测试前记录

- 测试日期和时区。
- 设备型号、Android 版本、系统 Build 与增量版本。
- AIUI Runtime / Craft 可见版本。
- 本仓库源码提交号。
- 是否重启过设备、是否刚从其他语音应用切换过来。

不要在公开记录中保留设备序列号、账号、Wi-Fi、通知、联系人或本机绝对路径。

## 固定语句

每一轮严格使用以下无个人信息语句：

1. “王秘书说他凌晨一点半”。
2. 自然停顿 2 至 3 秒。
3. “在蓝色会议室”。
4. 自然停顿 2 至 3 秒。
5. “桌上放着一份文件”。

语速保持日常说话水平，不要故意连读，也不要为了触发异常突然加快操作。

## A. 单次识别基线

1. 打开应用，选择“单次识别基线”。
2. 单击开始，说“王秘书说他凌晨一点半”。
3. 等待原生 `onend` 和页面回到 READY。
4. 重复 3 次。
5. 记录每次是否有 `onstart`、`onresult`、`onend` 或 `onerror`。

如果基线也无法正常工作，本轮不能用来证明自动重启问题。应先记录为环境或基础识别异常。

## B. 自动续听复现

1. 选择“自动续听复现”，单击开始。
2. 按“固定语句”完整完成一轮。
3. 不退出页面，继续重复固定语句至少 10 轮，或直到出现长时间无回调。
4. 页面显示 `watchdog_no_callback` 时，先截屏并记下当前 RUN / SEGMENT，不要立刻调用其他操作掩盖现场。
5. 记录结束后单击停止或按返回键，使应用主动 `abort()` 并释放对象。

自动模式只在原生 `onend` 后延时 300ms 调用下一次 `start()`；15 秒观测不会中止或重启 ASR。

## 复现判定

“疑似复现”必须同时满足：

- 已有 `segment_start_request`，且本测试此前至少一个分段完成过正常生命周期；
- 自最后一次原生回调起达到 15 秒；
- 期间用户按协议开口；
- JavaScript 侧没有新的 `onresult`、`onerror` 或 `onend`；
- 没有应用主动停止、切页、失焦或系统权限弹窗能直接解释该空档。

`watchdog_no_callback` 只是观测标记，不自动等同于已确认 Bug。必须结合视频、操作笔记和原始日志复核。
